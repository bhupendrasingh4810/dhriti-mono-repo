# Deployment Runbook

The repository contains API and web Dockerfiles, a local API Compose stack, and Terraform for managed Redis. The Compose stack runs PostgreSQL, Redis, an API migration job, and the API; its migration job uses `db:migrate:deploy`.

No executable production CI/CD or application hosting workflow is checked in. Treat the following as a verification checklist rather than a production procedure:

1. Build the application image using the relevant Dockerfile.
2. Apply committed Prisma migrations with `db:migrate:deploy`.
3. Verify `/v1/health/ready` can reach PostgreSQL and Redis.
4. Verify `/v1/metrics` is reachable by the configured metrics collector.

## Connect Security Checks

1. Confirm `CORS_ORIGINS` and `CONNECT_SOCKET_ALLOWED_ORIGINS` contain only approved HTTPS web origins.
2. Confirm the deployment secret manager supplies `AGORA_APP_CERTIFICATE`; it must not be present in browser bundles or client environment variables.
3. Confirm Redis is available before deployment. It distributes Connect socket presence and forces active sockets to disconnect after a session is revoked.
4. Apply and verify the Connect call migration before enabling calls. The API persists call state in `connect_calls` and `connect_call_participants`.
5. Verify recording remains disabled unless an approved consent, storage, retention, and deletion workflow has been deployed.

## Security Center and SSO rollout

- Apply `20261117190000_security_center_oidc` and `20261118040000_security_center_operations` before starting the API: the global HTTP IP guard intentionally depends on the blocklist table and fails closed if its database is unavailable. The latter migration is additive, preserves existing permanent blocks, and adds alert delivery persistence.
- For client-IP detection behind the Next BFF, configure the web server with `TRUST_INGRESS_CLIENT_IP=true` **only** when your trusted ingress overwrites `X-Real-IP` with one validated client address. Also enable API `TRUST_PROXY=true` and restrict API network access to that proxy. Without this opt-in, forwarded client headers are ignored and the API sees the BFF address; do not mistake it for an individual user's address. Incorrect proxy trust can either block shared users or let attackers spoof IPs.
- Cookie-authenticated BFF mutations require an Origin matching the web origin. Configure the ingress to preserve the canonical host/protocol; cross-origin cookie form submissions must receive 403.
- Test Block/Unblock using a separate test-client address. Current-IP self-blocking is rejected. Maintain an operator recovery path to remove a mistaken block directly from `blocked_ips`; no unauthenticated bypass endpoint exists.
- Supply `OIDC_ALLOWED_ISSUERS`, `SECRETS_ENCRYPTION_KEY`, and Redis 6.2+ before enabling SSO. Preserve the encryption key across deploys. Register the exact web callback URL and verify HTTPS cookies in production.
- Built-in detection currently covers repeated password failures only. Add upstream WAF/IdP/SIEM feeds separately for geographic anomalies, API abuse and leaked-token detection; those signals are not inferred from sample dashboard text.
- Configure optional `SECURITY_ALERT_EMAILS` with the existing `BREVO_*` delivery settings. Configure an operator-approved HTTPS `SECURITY_WEBHOOK_URL` and a separate `SECURITY_WEBHOOK_SECRET` for signed exports; restrict outbound network access to that collector. Treat findings and recipient addresses as sensitive operational data.
- For actual upstream SIEM/WAF/IdP findings, configure `SECURITY_INGEST_TOKEN` and an adapter that sends the normalized [security event contract](../api/authentication.md#email-alerts-and-generic-siemwaf-integrations). Keep ingestion and signing secrets distinct, distribute out of band and never include them in logs. No live provider is enabled by merely deploying this code.
- Monitor **Alert delivery history**. Failures retry up to eight times; after fixing connectivity/configuration use **Retry delivery**. Network sends are at least once; collectors must verify HMAC/timestamps and deduplicate delivery IDs. Workers run every five seconds; destinations enabled later do not receive historical backfill. No test emails/webhooks are sent automatically.
- Validate a temporary IP block from a separate address: expiry must stop enforcement immediately without a cleanup job. Preserve manual DB unblock access for recovery. CIDR blocks and automated account suspension are intentionally unsupported.
- Test session revocation with a second browser, including immediate access/refresh rejection and socket disconnect; verify Redis availability. Self-revocation signs the operator out. In the compliance panel, distinguish historical verified SSO from enabled/unverified configuration and local MFA enrollment gaps from provider-verified MFA claims.

## System Health dashboard

- `GET /v1/control/platform/system-health` returns a typed snapshot; `GET /v1/control/platform/system-health/report` returns the same JSON as an attachment. Both use platform-role authorization (`PLATFORM_ADMIN`, `ENGINEERING`, `SECURITY`) and `Cache-Control: no-store`; no provider credentials, raw errors or connection URLs are returned. Existing `/health/live` and `/health/ready` probes are unchanged.
- Sampling is **per API instance**, not fleet-wide. The server coalesces concurrent readers/report downloads and caches each snapshot for 30 seconds; a nominal 30-second background sampler keeps bounded in-memory observations. Sampling is not a precise scheduler, and a cached snapshot may be reused at a timer boundary. Availability uses at most the last 24 hours / 2881 observations and resets on process restart; degraded checks count as available, unavailable checks are excluded. This is observed sample availability, **not an SLA or continuous historical uptime**. Downloaded reports include sample counts, instance ID and observation-window metadata.
- Primary PostgreSQL uses a read-only `SELECT 1` transaction with a 3s statement timeout, 1s pool wait and 4s transaction deadline. Redis uses `PING`. S3 uses `HeadBucket` with a 5s abort deadline and requires bucket-metadata permission; a 403 is reported as unavailable, not an outage, because the monitor cannot establish whether object writes work. All probes have a 5s response bound, and unresolved underlying probes are reused instead of accumulating requests.
- Auth checks local access-token signing/verification plus primary/Redis dependency availability; they do not simulate a user login. The API row uses instrumented process-lifetime HTTP p95 latency and interval 5xx rate. Checks at/above 500ms are degraded; API interval 5xx above 1% also degrades its row.
- WebSocket status reports local `/connect` initialization and Redis dependency, not an external socket round trip. **Active Connections** counts instrumented `/connect` sockets only. The five-minute change appears only with a baseline 5–6 minutes old; HTTP, database and other socket namespaces are not included.
- Configured Brevo email checks read the provider account endpoint over HTTPS with a 5s deadline. This validates provider API access, **not actual email delivery**, and never sends test messages. Without Brevo configuration the row is unavailable.
- Preserve the replica, Elasticsearch and CDN rows as **unavailable** until independently instrumented. No replica/CDN monitor exists here; actual application search uses PostgreSQL, not Elasticsearch. Unavailable rows do not inflate Operational/Degraded/Outage totals; hover a row for scope/reason.
- CPU is API-process CPU time normalized over available logical CPUs; memory is API-process RSS divided by host-reported RAM, not container/fleet utilization. Disk I/O and network percentages remain unavailable until an infrastructure collector provides those measurements. Hover resource readings for scope.
- The web UI loads once on mount and thereafter only on **Refresh** or **Retry**; it does not poll on a timer or on window focus. Requests time out after 15s, concurrent refreshes are disabled, and mounted rows/readings remain visible during refresh or failure. Inline skeletons appear only on initial load. Last Check uses an absolute local time (full timestamp on hover), not a frozen relative age. The displayed sample timestamp may lag Refresh by up to the server's 30-second shared cache interval; background server sampling remains independent of browser requests.
- **Download Health Report** opens PDF/JSON choices without fetching until a format is selected. JSON downloads the authenticated snapshot. PDF generation runs locally in the browser (no external conversion service), opens the actual PDF in the shared Dhriti-themed canvas preview (page navigation, zoom and Fit width), and downloads those identical bytes only on **Download PDF**. The locally bundled PDF.js worker replaces browser-owned viewer chrome; deployment CSP must allow same-origin workers. Preview failures appear inline without disabling the original download. Exported availability remains sampled, per-instance data, not an SLA. Portable built-in PDF fonts use theme-derived sizing/colors; unsupported font characters are explicitly encoded as `[U+codepoint]`, while JSON preserves original Unicode. Export failures show an error, never a success toast.
- Because this page is authenticated and global authorization/IP checks need the database, a complete database outage may prevent fetching the dashboard itself. Keep independent readiness/Prometheus infrastructure monitoring; do not treat the admin page as an out-of-band monitoring system.
